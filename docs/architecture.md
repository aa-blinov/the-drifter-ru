# Architecture

Как устроена русская локализация The Drifter.

## Форма игры

The Drifter сделан на Unity 2020.3, движке PowerQuest от Powerhoof. Текст игры лежит
в одном MonoBehaviour `PowerTools.Quest.SystemText` внутри
`TheDrifter_Data/sharedassets1.assets`. В каждой строке лежит одна запись:

| Поле | Что в нём |
| --- | --- |
| `m_character` | Кто говорит: `Narr`, `Mick`, `Roth`, `Detective`, пусто для служебного текста |
| `m_id` | Номер строки внутри персонажа |
| `m_sourceFile` | Файл сценария: `Room- LabReactor`, `Dialog- CeoLab`, `Item- Zippo` |
| `m_sourceFunction` | Функция: `OnInteractHotspot`, `OptionTopicQuantum`, `UpdateDescription` |
| `m_string` | Сама строка на английском |
| `m_translations` | Массив по языкам; в локе «Custom» лежит перевод |

Ключ строки в игре состоит из пары `(character, id)`. Одна и та же английская строка
встречается в разных местах, и перевод обязан совпадать во всех.

## Два пути, которыми игра читает перевод

**translation.csv.** Игра читает файл `translation.csv` из своего каталога.
Формат фиксирован импортёром:

```
Character,ID,File,Context,English,Русский
Narr,0,Room- Title,NewGame,I'd jumped the car back in Breaker's Cut,Я запрыгнул в машину в Брейкерс-Кат
```

Импортёр открывает файл как `Encoding.Default` с определением BOM, поэтому
файл должен быть UTF-8 **с BOM** и с CRLF. Имя языка лежит в последней ячейке
заголовка; оно же показывается в Options → Language.

**Файлы ассетов.** Слот «Custom» в самом `SystemText` пуст, пока игру не
установят: именно наличие `translation.csv` заставляет игру зарегистрировать
язык. Поэтому комьюнити-патчи кладут текст в CSV, а в ассетах меняют только
шрифты.

## Пайплайн

```
corpus/english.csv
     │
     ▼
  extract_corpus.py ──► work/corpus/corpus.jsonl
     │
     ▼
  translate.py --stage bulk        перевод
     │                              work/corpus/bulk.jsonl
     ▼
  translate.py --stage editorial    редакторский проход
     │                              work/corpus/edit.jsonl
     ▼
  translate.py --stage manual      ручные правки
     ▼
  canonicalise.py                  одна строка, один вариант
     │                              work/corpus/canon.jsonl
     ▼
  typography.py                    типографика: …, «ёлочки», тире
     │                              work/corpus/typo.jsonl
     ▼
  polish.py                        дефекты, которые нашёл QA
     │                              work/corpus/polish.jsonl
     ▼
  proofread.py                     вычитка против источника
     │                              work/corpus/proofread.jsonl
     ▼
  translate.py --stage manual      ручные правки
     │                              work/corpus/final.jsonl
     ▼
  qa.py                            проверки
     ▼
  build.py ─────────────────────► translation/Russian/translation.csv
```

| `src/drru/corpus.py` | Загрузка корпуса, ключ строки, формат CSV игры. |

| `src/drru/llm_client.py` | Эндпоинт, дисковый кэш, разбор ответа. |
| `src/drru/translate.py` | Перевод, редакторский проход, ручные правки. |
| `src/drru/canonicalise.py` | Сводит варианты одной строки к одному. |
| `src/drru/typography.py` | Типографика: многоточие, «ёлочки», тире, снятие лишних кавычек. |
| `src/drru/polish.py` | Переводит заново строки, которые проверки нашли сломанными. |

| `scripts/glossary_expand.py` | Спрашивает у модели русскую форму термина по строкам, где он встречается. |
| `scripts/render_glossary.py` | Рендерит `docs/glossary.md` из `src/voice/glossary.json`. |
| `scripts/measure_widths.py` | Измеряет ширину русской строки по шрифтам игры. |
| `scripts/lore_inventory.py` | Инвентарь сущностей текста: сколько раз имя встречается и есть ли оно в глоссарии. |
| `scripts/chronology.py` | Все временные ссылки текста: годы, числа с единицами, слова времени. |
| `scripts/voice_audit.py` | Ищет строки, где перевод потерял голос источника. |
| `scripts/voice_apply.py` | Отбирает находки аудита и применяет правки, прошедшие фильтры. |

## Решения, которые стоит знать

### Глоссарий замораживается до основного текста

Термины и имена переводятся первыми, малыми батчами, и больше не трогаются.
Каждый следующий этап получает глоссарий и привязан к нему.

Цена это этап в начале пайплайна и модельные вызовы, которые иначе ушли бы в
основной проход с худшим результатом: термин, решённый в батче 40 и
использованный в батче 2000, это два слова для одной вещи.

### Батч не пересекает файл сценария

Батчи режутся внутри `m_sourceFile`, поэтому реплики одной сцены доходят до
модели вместе. Модель видит, кто говорит и что было сказано секунду назад, и
голос персонажа выживает.

Цена это переменная длина батча и пересборка промпта под каждый.

### Второй редакторский круг читает первый

Редактор проходит по корпусу дважды. Во втором круге в промпт идёт хвост
предыдущего батча, так что голос, установленный в первом круге, распространяется
вперёд, а не каждый батч решает заново.

Цена это ещё один проход по корпусу и зависимость от порядка строк.

### Reasoning выключен

`minimax-m3` с включённым reasoning тратит 186 секунд на батч из сорока строк
и 4.6 секунды с выключенным. Для перевода рассуждение ничего не добавляет.
Клиент по умолчанию шлёт `reasoning: {"effort": "none"}`.

### Канонизация идёт после редактуры

Редакторский проход может оставить одну и ту же английскую строку в двух
разных вариантах: он видел их в разных батчах. Канонизация собирает варианты
каждой повторяющейся строки и сводит их к одному.

### Вычитка читает текст, а не сканирует его

Что вычитка приняла и что отвергла, с причинами, записано в
`docs/proofreading.md`.

Сканер ИИ-паттернов ищет следы машинного письма. Вычитка ищет другое: строку,
которая говорит не то, что говорит источник, потеряла факт или оставила
английское слово.

```bash
python3 src/drru/proofread.py
```

Модель читает каждую строку перевода рядом с её английским источником и
называет расхождения. Это измерение, а не приговор: каждое замечание читается
человеком, и то, что источник не подтверждает, остаётся как есть. На 9803
строки модель даёт около 500 замечаний, из которых настоящими дефектами
оказываются десятки.

Цена это один полный проход по корпусу и модельные вызовы.

### Терминология проверяется по тексту, а не по списку

Глоссарий это обещание: у термина одна русская форма. Проверка читает строки,
где термин встречается в источнике, и смотрит, каким словом он переведён.
Термин, у которого в тексте две формы, это дефект: игрок читает одного
человека под двумя именами.

```bash
python3 scripts/check_terms.py
```

Падежные формы дефектом не считаются: «Рот», «Рота» и «Ротом» это одно слово.

### Один термин, одно слово: закон, который держится на глоссарии

Глоссарий замораживается до текста, и кажется, что этим правило закрыто.
На деле оно закрывает только имена и обычные слова. Термины игры
(`phase-flip`, `quantum coupler`, `live wire`, `blast door`) на момент
заморозки ещё нигде не встречались, а глоссарий пишут по тому, что уже
известно. В глоссарии на момент перевода их не было.

А батчи не пересекают границы файлов сценария: так реплики одной сцены
доходят до модели вместе. Значит, каждый файл переводит один и тот же термин
заново, своими словами.

Измерено на `phase-flip`:

| Файл сценария | Как в нём написан термин |
| --- | --- |
| `Room- LabInterface` | фазовый сдвиг |
| `Item- TopicCartridge` | фазовое переключение |
| `Room- LabVent` | смена фазы |
| `Dialog- SisterLab` | фазовый переход |
| `Dialog- HideoutCell` | фазовый переворот |

Пятнадцать файлов дают шестнадцать вариантов. Та же формула и для остальных
терминов: `receptionist` даёт шесть файлов и семь вариантов, третий основатель
пять файлов и шесть вариантов.

Дальше стадии не помогают. Редакторская переписывает 2885 строк из 9803 и не
унифицирует ни одного термина: она работает с предложением, а не со словом.
Типографика занимается знаками, канонизация повторами, полировка дефектами,
которые нашла QA. Ни одна стадия не смотрит на корпус целиком и
не сравнивает термин в разных строках.

Хвост предыдущего батча (четыре строки) переносит интонацию, и промпт
прямо просит «не переводить заново». Слово он не переносит.

Отсюда два практических следствия:

1. **Глоссарий нужно дополнять до перевода, а не после.** Термин, которого
   в нём нет, будет переведён заново в каждом файле.
2. **Терминология чинится проходом по всему корпусу.** Проверка строки
   этого не видит: строка может быть прекрасной, а термин в ней четвёртый
   по счёту. `scripts/check_terms.py` сравнивает термин по всем строкам, где
   он встречается.

Когда термин не был закреплён, модель изобретает и несуществующие слова:
`секретарку`, `муфтрон`. Это не опечатка, а следствие того же закона.

#### Проверка закона

Закон проверялся экспериментом: тот же корпус, тот же голос, тот же
размер батча и глоссарий на 275 записей вместо 193.

```bash
python3 -m src.drru.translate --stage bulk --out work/corpus/bulk_trial.jsonl
python3 scripts/compare_terms.py work/corpus/bulk.jsonl work/corpus/bulk_trial.jsonl
```

Считаются разные слова, падежи одного слова не считаются.

| Термин | Глоссарий 193 | Глоссарий 275 |
| --- | --- | --- |
| `phase-flip` | 5 слов | **1**, фазовый переворот |
| `blast door` | 3 слова | **1**, взрывная дверь |
| `business ID` | 4 слова | **1**, регистрационный номер |
| `receptionist` | 4 слова | **1**, рецепционистка |
| `third founder` | 2 слова | **1**, третья соучредительница |
| `reactor floor` | 2 слова | **1**, пол реактора |
| `quantum coupler` | 3 слова и несуществующее «муфтрон» | 2 слова, оба из глоссария |
| `live wire` | 1 слово | 2 слова, один проскок модели |

Двадцать четыре слова на десять терминов стали десятью. Закон держится: слово термина даёт **глоссарий**, а не батч и не файл
сценария.

Исключение одно, `live wire`: модель один раз написала «оголённый провод»
вопреки глоссарию. Связывание сильное, но не абсолютное, и поэтому
проверка по корпусу нужна всегда.

Пробный корпус это измерение, а не замена. Он не идёт через редакторскую,
типографскую и полировочную стадии, и поставляемый текст им не
переписывается: вычитанный руками перевод содержит правки вычитки,
которых в свежем прогоне не было бы. Пробный прогон повторяют, когда нужно
проверить глоссарий, а не чтобы получить новый текст.

### Инвентарь сущностей

Глоссарий знает то, что в него вписали. Текст знает больше: имена, которые
никто не записал, и именно они разъезжаются первыми.

```bash
python3 scripts/lore_inventory.py            # имена и их частота
python3 scripts/lore_inventory.py --show Roth   # строки, где имя встречается
```

Имя, которого нет в глоссарии, это имя, которое может разъехаться.
Инвентарь показывает, какие именно.

## Проход по голосу

Вычитка ищет смысл, и смысл она находит: строка, которая говорит не то, что
говорит источник, видна сразу. Плоская строка видна иначе: она верна по
смыслу и звучит как пересказ, и ни одна проверка этого не скажет.

Для этого есть отдельный проход, `scripts/voice_audit.py`. Модель получает
английский источник и русскую строку рядом и называет места, где оттенок
источника не доехал: интонация, характер, усталость, сарказм. Находок на
9 803 строки вышло 1 914, почти пятая часть корпуса.

Модель ошибается в обе стороны: она находит то, чего нет, и предлагает
правку хуже исходной. Поэтому находка проходит фильтры
(`scripts/voice_apply.py`), а решение принимает человек. Фильтры отсекают
сдвиг термина глоссария, потерю числа, плейсхолдера и разметки, смену лица
повествования, чужой алфавит и поломанную типографику: всё это правка
делает чаще, чем хочется.

Каждая применённая правка проходит вычитку заново. Вычитка нашла в
применённых правках 248 строк со сдвигом смысла, и все они вернулись к
прежнему тексту. Проверка `test_one_english_line_has_one_russian_line`
поймала ещё случай: правка одной строки разошлась по дубликатам английского
источника, потому что английская строка встречается в игре больше одного
раза, а правка пришлась только на один её экземпляр.

Запись прохода с числами: `docs/proofreading.md`.

### Проверка лора

Перевод меняет смысл в предложениях и в фактах: кто чей родственник,
какая болезнь, кто третий основатель, что называется титулом. Такое расхождение не видно ни в проверке строки, ни в сверке с
английским источником: это видно только тогда, когда известно, кто кому
кто.

```bash
python3 scripts/check_terms.py
```

Лор сверяется с открытыми источниками: с пересказом сюжета в Википедии, с
рецензиями и с самой игрой. Где публикации расходятся с игрой, правы игры:
она первоисточник. Что сошлось и что исправлено, записано в `docs/lore.md`.

### Шрифты правит установщик, а не репозиторий

Файлы игры принадлежат разработчику. Установщик читает копию, которую
владелец купил, и пишет в неё `translation.csv` и шрифты с кириллицей;
оригинальный `sharedassets1.assets` остаётся в `_ru_backup`.

## Шрифты

Текст рисуют семь шрифтов из ассетов игры. Ни один из них не содержит
кириллицы, и без патча русская строка рисуется системным шрифтом: она читается,
но выглядит чужой рядом с английской.

Кириллица добавляется в шрифты из пиксельного Ark Pixel Font, и масштабируется
по x-height латиницы того же шрифта: так русская строка имеет ту же плотность
и стоит на той же базовой линии. Шрифты игры векторные, с хинтингом, и
рисование идёт как есть.

Ассеты патчатся побайтно, а не пересборкой: `UnityPy` при записи файла
теряет данные всех объектов, которые не разобрал, и файл в 30 МБ приходит
в 1.3 МБ. Игра с таким файлом не запускается.

## Границы

- **`src/drru/llm_client.py` ничего не знает об игре.** Он вызывает эндпоинт и
  кэширует ответы. Всё игровое лежит в слоях выше.
- **Этапы не импортируют друг друга.** Каждый читает файл и пишет файл;
  промежуточные файлы в `work/` это запись того, что делал каждый этап.
- **`tests/` не импортирует `src/`.** Тесты читают `translation.csv` так, как
  это делает игра, и проверяют то, что увидит игра.
- **Ширина строки измерена, перенос в панели нет.** Ширина считается по
  настоящим шрифтам из ассетов; числа и как они получены, в
  `docs/layout.md`. Ширина самой панели в пикселях в шрифтах не хранится,
  поэтому сказать, где именно перенос станет хуже, чем в оригинале, нельзя;
  известно только, что русский текст занимает не больше места, чем английский.
